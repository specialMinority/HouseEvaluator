# Phase 6~7 구현 검증 기록

기준일: 2026-09-13 · 로컬 브랜치 `codex/houseevaluator-v2`.

이 기록은 연동·검증·제한 공개 기반 프로그램의 로컬 검사 결과다. 실제 공급 계약, 실제 시장 정확도, 인터넷 서비스 운영과 제한 공개 완료를 의미하지 않는다. 모든 운영 훈련 자료는 합성 또는 빈 공급 설정이며 시장 출시 증거로 등록하지 않았다.

## 독립 검토 후 수정

- 계약 설정을 수집 직전과 응답 후 다시 검사하여 철회된 자료 반입을 차단했다.
- 현재 스냅숏이 삭제된 뒤 304 또는 같은 파일 응답을 수집 성공·최신 자료로 처리하지 않도록 했다.
- HTTPS 수신과 HTTP 서버 요청에 전체 시간 제한을 적용했다. 헤더·본문을 조금씩 보내도 작업 슬롯을 무기한 점유하지 못하는지 확인했다.
- 시장 보고서의 개별 승인 기준 중 하나라도 실패·누락되면 승인하지 않는다. 숫자 `1`을 불리언 `true`로 인정하지 않는다.
- 승인되지 않은 도시의 최신 자료가 승인 도시의 오래되거나 부족한 자료를 가리지 못하도록 구간별 20호실·10건물·핵심 필드 가용성을 확인한다.
- 운영 증거 fingerprint에 모든 v2 Python 모듈, HTTP 서버, 프런트엔드와 공급 설정을 포함했다.
- 잘못된 접속 코드를 입력했을 때 두 번째 인증 실패 요청이 오류 문구를 지우던 화면 동작을 수정했다.

## CLI와 복구 훈련

빈 공급 설정으로 수집기 `--once`와 `--status`를 실행했다. 외부 요청 0건, 시도 0건, 공급원 0개, `not_configured`를 확인했다.

복구 훈련은 합성 3개 공급원·72호실 DB에서 수행했다. 온라인 백업 후 임시 신규 경로에 복구하여 백업 체크섬·크기·매니페스트 개수·수신 기록 해시·복구 개수·스냅숏 해시를 모두 확인했다. 운영 DB는 교체하지 않았고 임시 복구 파일을 정리했다. 보고서는 `passed=true`, `scope=synthetic_smoke`, `evidence_registered=false`다.

보관 정리는 계획 모드로 실행했다. 당시 삭제 대상 스냅숏 0건·백업 0건·차단된 백업 0건이었고 삭제는 적용하지 않았다. 만료·철회 삭제 및 손상 거절은 자동 테스트에서 확인했다.

## 실제 브라우저

- 인증 전 API 접근 차단과 접속 코드 입력 화면.
- 잘못된 코드 제출 시 오류 안내 유지, 올바른 코드 제출 시 공급 상태·역 목록 갱신.
- 인증 후 명시적 도쿄 합성 시연: 24호실·12건물, 합성 대표가격 94,500엔, 실제 시세 아님 표시.
- 접속 코드 삭제 시 비교 결과와 시연 입력 초기화, 새로고침 후 재인증 필요.
- 이전 Phase 5에서 세 도시·390px 모바일·비용 계산을 확인했으며 이번 단계는 추가된 접속 흐름을 확인했다.

## 공개 준비 검사

빈 실제 공급 설정·미승인 레지스트리·미승인 운영 증거로 `check_v2_release.py`를 실행했다. 결과는 `ready=false`, `eligible_segments=[]`, 실제 최신 매물 0건이다. 계약·시장 검증·수집·운영 훈련·비용 확인·운영자 승인 기준은 미충족이다. 합성 복구/부하 보고서는 공개 증거에 등록하지 않았다.

이 CLI는 데모/레거시 비활성의 로컬 실행 구성을 검사하며 실행 중인 합성 시연 서버 설정을 읽지 않는다. 실제 서버 상태는 인증된 `/api/v2/readiness` 응답으로 확인해야 한다.

재현 보고서는 Git 제외 경로 `.runtime/reports/phase67-restore.json`, `phase67-load.json`, `phase67-readiness.json`에 저장했다. 당시 코드/설정 fingerprint는 `b1f3fba2cd1dc66587103aef86142b2fd0227d0eb9dbcff706c9e556abc9533e`다. 프로그램 또는 공급 설정이 바뀌면 운영 증거를 다시 생성해야 한다.
