# 공급사 없는 개인 매물 비교

기준: 2026-09-13. 현재 기본 진입은 이 개인 비교 화면이다. 공급 계약·API 키·유료 서버 없이 기존 PC에서 실행한다. `DEVELOPMENT_PHASES.md`의 P1~P5에서 구현과 검증을 추적한다.

## 실행과 사용

저장소 루트에서 Python 3.12 이상으로 `python -m backend.src.server`를 실행하고 `http://127.0.0.1:8000/frontend/v2/`를 연다. npm 설치나 프런트엔드 빌드는 없다.

1. 대상 집의 도시, 행정구역, 일본어 역명, 평면, 면적, 월세를 입력한다. 같은 건물군 비교를 위해 **광고 건물 종류(맨션/아파트), 지상 총층수, 구조, 거주 층**을 함께 확인한다. 엘리베이터, 관리비·준공·도보도 알면 입력한다. 미상은 비워 두고, 관리비가 없다고 확인된 때만 0을 쓴다.
2. 자동 검색을 실행한다. 현재 어댑터는 SUUMO이며 도쿄 23구, 오사카시 24구, 후쿠오카시 7구를 지원한다. 지역 목록을 참고해 원문 행정구역을 입력한다.
3. 찾은 광고의 원문·조회 시각·미상 항목을 확인한다. **조건 확인·수정** 또는 **직접 입력**으로 보완한다. 자동 검색 실패 시에도 기존 입력·목록은 유지한다.
4. 목록 상단·하단 또는 화면 하단 고정 바에서 비교한다. 결과 상단에서 가까운 매물과 내 집의 가격 그래프·표본 내 가격순위를 보고, 바로 아래의 매물명·조건 차이·원문 링크를 확인한다. 검색 범위, 주 비교 통계와 완화 단계는 상세 영역에서 확인한다. 결과 보기로 언제든 돌아갈 수 있다.

화면의 대상 예시는 입력 방법을 보여주는 가상의 집이다. 실제 비교 매물이나 과거 집계 가격을 자동 삽입하지 않는다. 새로고침하면 브라우저의 입력과 목록이 사라진다.

## 자동 검색의 범위

공개 검색은 사용자가 요청할 때만 수행한다. 가까운 면적 범위를 사이트의 실제 선택값으로 바깥 반올림해 검색하고, 필요하면 최대 ±20%를 포괄하는 검색으로 넓힌다. 광고 건물 종류가 명시된 경우 검색 조건에 반영한다. 필수 검색 폼의 가격 하한 없음/상한 없음 값은 고정하며 **대상 월세로 후보 가격대를 제한하지 않는다**.

검증된 역 메타데이터가 없으면 시·구·정·촌 목록에서 대상 역의 노선명을 관측하고, 공식 노선·역 선택 폼의 명칭과 값을 정확히 대조해 역 검색으로 전환한다. `小岩`과 `新小岩`을 부분 일치시키지 않고 역 코드도 추측하지 않는다. 확인된 탐색 메타데이터만 제한된 프로세스 메모리에 재사용하며 매물 가격을 캐시로 채우지 않는다. 역을 확인하지 못하면 구 전체 대체 검색임을 표시한다.

전체 45초 안에서 **최대 3개 목록 페이지·24개 상세 페이지**를 확인한다. 최초 역 확인에 사용하는 구 목록도 3페이지 예산에 포함된다. 다음 페이지는 원문에 실제 존재하며 검색 조건이 같은 `page=2/3` 링크만 따른다. 목록 파서는 최대 50개 건물 카드에서 카드당 유효 광고 8개를 반환한다. 한 건물의 방이 많아 뒤쪽 건물을 읽기 전에 중단하지 않으며, 범위 밖 후보가 상세 예산을 사용하지 않게 거른다. 유사 건물군 안에서 건물별로 순환한 뒤 면적·관측한 건물 나이 등을 확인한다. 상세는 알려진 주소+건물명당 1개씩 먼저 조회한 후 최대 2개까지 확인한다. 개별 상세의 404/410은 해당 건만 건너뛰며, 접근 제한은 추가 조회를 중단한다. `築n年`은 정렬 보조일 뿐 준공 연도를 사실로 만들어 채우지 않는다.

검색 보고서는 해석한 페이지, 읽은 광고행(페이지 간 중복 포함), 반환 광고, 대상 역 포함 광고, 주소+이름으로 구분한 잠정 건물, 상세 요청·반영, 실제 조회 링크와 중단 사유를 구별한다. 제한된 페이지와 원문 기본 정렬에 따른 누락이 있으므로 **주 비교 0개는 이번 검색에서 확인하지 못했다는 뜻**이며 주변 시장에 매물이 없다는 뜻이 아니다.

검색 시 [SUUMO robots.txt](https://suumo.jp/robots.txt)를 확인한다. 거절된 경로, 인증·CAPTCHA, 403/429 응답을 만나면 추가 조회를 중단한다. `robots.txt`는 재배포 허가나 서비스 계약을 뜻하지 않는다. 공개 페이지를 읽을 수 있다고 해서 공급 데이터의 권리·품질 검증을 통과한 것으로 취급하지 않는다.

현재는 정확한 `https://suumo.jp` 호스트의 허용된 검색·상세 경로만 서버에서 읽는다. URL 입력 필드는 출처 표시용이며 그 URL에 임의로 접속하지 않는다. 리다이렉트·사설 IP·임의 프록시를 사용하지 않는다. 페이지 크기·DNS·연결·전체 검색 시간(45초)을 제한하고 HTML 파서도 크기와 깊이를 제한한다.

관리비 `-`는 미상이다. 건물 종류가 맨션이라는 이유로 RC를 추정하지 않는다. 준공 연도는 상세 페이지의 명시된 값만 사용한다. 도보 시간은 해당 역의 접근 정보와 묶으며, `新宿`과 `西新宿` 같은 부분 일치는 허용하지 않는다.

조회 시각은 그 페이지를 읽은 시각이다. 현재 공실, 계약 가능 여부, 모집 상태를 확인한 시각이 아니다. 광고 갱신일도 날짜만으로 상태 확인 시각을 만들지 않는다.

## 가까운 매물의 가격 그래프와 순위

주 비교가 없더라도 `visual_comparison`으로 가장 가까운 참고 매물과 대상의 실제 광고 가격을 나란히 보여준다. 그래프의 모집가격 차이는 층수·면적·연식 등의 차이를 보정한 가격 효과가 아니다. 기존 주 비교·참고군의 통계와 별도의 표시 표본이며 기존 요약·제외 규칙을 바꾸지 않는다.

- 주 비교가 1개라도 있으면 그 표본에서만 고른다. 없으면 참고군 중 건물 조건의 일치·미상·차이 우선순위가 가장 가까운 한 단계에서 고른다. 확인된 일치 조건으로 충분히 좁힌 표본에 다른 건물군을 추가해 개수를 채우지 않는다.
- 건물 종류 → 구조군 → 3층 이하/4층 이상 → 승강기 → 거주 위치 순으로 확인된 일치, 미상, 차이를 구분한다. 같은 단계에서는 총층수·면적·준공 연도·도보·거주 층의 차이 순으로 정렬한다. 광고 가격과 관리비 확인 여부는 후보 선택에 사용하지 않는다. 시장 자료로 학습한 유사도 점수나 일치 확률은 아니다.
- 주소+건물명으로 구분한 건물마다 최대 1개, 최대 5개 광고를 표시한다. 식별 정보가 미상인 광고는 전체에서 최대 1개다. 서로 다른 광고명이 실제로 다른 건물임을 보증하지 않는다.
- 대상과 표시할 모든 광고의 관리비가 알려져 있으면 월세+관리비를 쓴다. 하나라도 미상이면 그래프·대상·순위·개별 차이를 모두 월세만으로 통일한다. 다른 상세 그룹의 금액 기준을 그래프에 섞지 않는다.
- 순위는 그래프의 비교 광고 N개와 대상 1개를 합친 **가격이 낮은 순서**다. 동률은 순위 범위로 표시한다. 예를 들어 대상 100,000엔과 비교 80,000/100,000/100,000/120,000엔이면 5개 중 공동 2~4번째다. 시장 전체 백분위, 추천 순위, 적정가격 등급은 계산하지 않는다.
- 개별 `delta_yen`은 대상 가격에서 해당 광고 가격을 뺀 값이다. 양수면 그 광고보다 대상이 비싸다. 서로 다른 참고군의 통합 중앙값·대상 대비 퍼센트는 새로 만들지 않는다. 후보가 없으면 대상 금액만 보여주고 순위는 `null`이다.

`visual_comparison.version=observed-price-1`, `mode=primary|nearest_reference|empty`로 구분한다. `pool_count`는 선택한 조건 단계의 후보 수, `displayed_count`는 실제 그래프의 비교 광고 수다. `subject.price_yen`, `comparables[].price_yen/delta_yen/similarity_order`, `rank.low_to_high/tied_to/total/lower_count/equal_count/higher_count`가 UI 계약이다. 원문 URL·조건 차이·미상 정보는 각 비교 광고에 유지한다.

## 개인 표본 비교 정책

`backend/v2/personal.py`의 `personal-3` 정책은 실제 시장으로 보정되지 않은 초기 비교 규칙이다. 가격 보정 계수나 종합 점수를 만들지 않는다. **같은 건물군 안에서 조건을 완화**하고, 다른 건물군은 **각각의 별도 참고가격**으로 제공한다. 8층 맨션의 주 비교 중앙값에 3층 아파트의 가격을 섞지 않는다.

### 먼저 구분하는 건물 조건

- `building_type`: 원문 광고의 맨션/아파트 분류. 기존 `property_type=apartment`는 공동주택 전체를 뜻하며 별개다. 명칭에서 RC·목조·승강기를 추정하지 않는다. 광고의 맨션/아파트 구분은 사업자나 포털마다 다를 수 있다는 [UR 설명](https://www.ur-net.go.jp/chintai/college/202202/000827.html)을 따른다.
- `building_floors`: 지하를 제외한 지상 전체 층수. 거주 층 `floor`와 분리한다. [총무성 통계국의 용어 정의](https://www.stat.go.jp/data/jyutaku/2023/pdf/g_yougo.pdf)도 건물 층수에 지하를 포함하지 않는다. 거주 층이 총층수를 초과하는 입력은 오류다. `2階/8階建`는 거주 2층·총 8층이다.
- 규모 구간은 1~3층 / 4~5층 / 6~10층 / 11~19층 / 20층 이상이다. 주 비교는 같은 구간이며 총층수 차이가 2층 이하여야 한다. 이 구간·허용치는 서비스가 선택한 보수적인 초기 규칙으로 법정 건물 분류나 검증된 가격 효과가 아니다.
- 구조군은 RC/SRC, 철골/경량철골, 목조로 구분한다. 다른 구조군을 주 비교로 완화하지 않는다.
- 거주 위치는 지하 / 1층·지상 접지층 / 중간층 / 최상층으로 나눈다. 같은 총층수라도 최상층과 중간층은 주 비교를 분리한다. 같은 위치 안에서 거주 층 차이는 시작 2층, 확대 후 최대 4층이다.
- `elevator`는 명시된 있음/없음/미상을 보존한다. 대상과 다른 상태의 표본을 주 비교에 섞지 않으며, 미상끼리의 비교도 미확인으로 표시한다. 광고에 설비가 안 나온다는 이유로 없다고 처리하지 않는다.

대상이나 매물의 건물 종류·총층수·구조군·거주 위치를 확인할 수 없으면 주 비교에 포함하지 않는다. 대신 원문과 확인된 조건을 유지한 별도 참고군을 제공하고 보완할 대상 항목을 안내한다.

| 조건 | 유지·완화 방식 |
| --- | --- |
| 도시·행정구역·역명·평면 | 항상 유지. 역명은 전각/공백/끝의 駅 정도만 정규화 |
| 면적 | 시작 ±5% → ±10%, 확대 참고 단계에서 ±20%까지 |
| 준공 연도 | 시작 ±2년 → ±5년 → ±10년, 최종 주변 참고 단계에서 해제 |
| 역 도보 | 시작 ±2분 → ±5분 → ±10분 |
| 방향 | 두 값이 확인되면 시작 단계에서 유지, 첫 완화에서 해제 |
| 거주 층 | 같은 거주 위치 안에서 차이 ±2층 → ±4층. 최상층 등 다른 위치는 별도 참고군. 확인된 지하·지상 차이는 참고군에서도 제외 |
| 구조 | 같은 구조 → 같은 구조군(RC/SRC, 철골/경량철골). 다른 구조군은 별도 참고군 |
| 신축 | 준공 연도 조건이 유지되는 동안 신축/기존 경계 유지, 최종 연도 해제 단계는 신축 포함이라고 표시 |
| 주택·계약·가구 | 둘 다 알려져 다르면 제외. 미상은 경고와 조건 차이에 표시 |
| 욕실 분리 | 시작 유지, 확대 단계에서 해제하고 차이 표시 |
| 연도·도보 미상 | 초기 단계에서는 제외. 미확인 항목을 명시하는 참고 단계부터 포함하며 값을 추정하지 않음 |
| 건물 종류·총층수·구조·거주 위치 미상 | 주 비교에 포함하지 않고 별도 미확인 참고군으로 표시 |

주 비교 단계는 방향 → 면적 ±10% → 연도 ±5년 → 도보 ±5분 → 연도·도보 등 미확인 조건 포함 → 거주 층 차이 ±4층 → 욕실 분리 해제 → 연도 ±10년 → 도보 ±10분 → 면적 ±20% → 같은 구조군 → 연도 해제 순서다. 위 건물 경계는 모든 단계에서 유지한다. 충분한 가장 앞 단계에서 멈추며, 끝까지 부족하면 표본이 가장 많이 확보된 가장 좁은 단계를 선택한다.

다른 건물군은 최종 주변 조건(같은 지역·역·평면, 면적 ±20%, 도보 차이 ±10분 등)을 만족하면 별도 참고군으로 제공한다. 그룹은 주택 유형·광고 종류·규모 구간·구조군·승강기·거주 위치별로 분리한다. 미상과 알려진 값도 서로 다른 그룹이다. 그룹 자체의 관찰 가격 범위와 표본이 충분할 때의 중앙값을 제공하되 **대상 대비 차이율은 계산하지 않는다**. 서로 다른 참고군을 합친 전체 중앙값도 없다. 그룹 순서와 후보 정렬은 가격과 무관하다.

참고군은 확인된 광고 종류·구조군·3층 이하/4층 이상 구분·승강기·거주 위치의 일치 여부, 총층수와 면적의 근접 순으로 보여준다. 위 다섯 특징이 모두 확인되어 일치하는 그룹에만 `same_building_features=true`와 “건물 종류·구조군·승강기 일치” 배지를 붙인다. 이 그룹들의 광고 수는 `related_reference_count`다. 예를 들어 대상 8층 RC 맨션과 5층 RC·12층 SRC 맨션은 승강기와 중간층 조건까지 확인되면 먼저 볼 수 있지만, 총층수·준공·면적까지 같다는 뜻은 아니다. 해당 그룹은 여전히 주 비교에서 분리하고 조건 차이를 표시한다. 미상끼리의 일치를 확인된 특징이라고 표시하지 않는다.

중앙값에는 매물 최소 3개와 주소·건물명으로 구분 가능한 건물 그룹 최소 3개가 필요하다. 1~2개나 건물 구분 부족이라도 개별 가격과 관찰된 최저·최고를 제공한다. 최저·최고는 추정 신뢰구간이 아니다. 조건이 미상인 표본을 동일 조건이라고 표시하지 않는다. 3개라는 수는 통계적 신뢰도를 검증한 기준이 아니다.

각 조건 단계에서 관리비 포함 표본이 충분하면 이를 사용한다. 관리비 미상으로 부족하지만 월세 표본이 충분하면 조건을 더 넓히기 전에 **대상과 모든 비교 매물을 월세만으로 통일**한다. 가격 차이·중앙값·범위·표가 모두 동일 기준을 사용한다. 월세 기준에서 대상 금액은 `rent_yen`이며 `rent_yen + mgmt_fee_yen`과 혼합하지 않는다. 관리비 미상을 0으로 처리하지 않는다.

결과는 주 비교와 별도 참고군을 구분한다. 주 비교의 가까운 조건 / 일부 완화 / 미상 포함 / 조건 확대를 표시하고, 각 그룹에 건물 종류·구조별 수, 총층수·준공·도보·거주 층 범위, 승강기 상태를 보여준다. 별도 참고군은 `reference_groups`, 그 표본 수는 `reference_count`이며, `input_count = matched_count + reference_count + excluded.length`를 유지한다. 참고군 표본을 제외 항목에 중복 계산하지 않는다.

같은 원문 URL, 주소·건물·층·면적 등에서 중복이 의심되는 광고는 보수적으로 묶는다. 같은 집으로 의심되는 광고의 알려진 가격·조건이 충돌하면 제외한다. 미상과 확인된 값의 차이만으로 충돌이라고 판단하지 않고, 일치하는 중복군에서는 가장 완전한 광고 한 개를 사용한다. 여러 광고의 항목을 임의로 합치지 않는다. 대상과 같은 URL·건물도 제외하며, 대상 식별 정보가 없으면 자기 매물 포함 가능성을 알린다. 이 추정은 공급사의 검증된 호실 ID를 대신하지 않는다.

중앙값·사분위는 각 건물 그룹이 같은 총 가중치를 갖도록 계산한다. 주소·건물명 미상인 광고는 하나의 미확인 그룹으로 묶으며, 최소 건물 수를 충족하는 데 사용하지 않는다. 가격 차이는 **선택 표본의 중앙값 대비 차이**다. 이를 시장 전체의 높음·낮음 등급으로 바꾸지 않는다.

## 실패와 운영

- 사이트가 변경되거나 거절하면 해당 출처 상태와 직접 입력 경로를 표시한다. HTML 변경을 빈 정상 검색 결과로 조용히 숨기지 않는다.
- `HOUSE_EVALUATOR_PUBLIC_SEARCH=0`으로 자동 검색만 중단할 수 있다. 직접 입력 비교는 계속된다.
- `HOUSE_EVALUATOR_PERSONAL=0`은 개인 기능 전체를 끈다. 기존 공급형 `HOUSE_EVALUATOR_PILOT=1`에서도 개인 API는 꺼진다.
- 작업은 비동기로 시작하고 결과를 조회한다. 검색 대기 취소 시 늦게 끝난 결과를 목록에 넣지 않는다. 이미 진행 중인 네트워크 요청은 자체 제한 시간까지 실행될 수 있으며 그동안 실행 슬롯을 유지한다.
- 서버의 검색 기록은 최대 32개, 생성 후 최대 15분 보관한다. 용량이 차면 완료·실패·취소된 기록 중 생성 시각이 가장 오래된 것을 먼저 지워 새 검색을 받는다. 15분 보관을 보장하지 않으며 지워진 작업 조회는 기존 만료 응답(404)을 반환한다. 대기·실행 중인 작업은 용량 확보를 위해 지우지 않고, 취소된 작업의 네트워크 실행 슬롯도 실제 종료까지 유지한다. DB·공급 스냅숏·백업으로 저장하지 않는다. 브라우저에 이미 가져온 목록은 페이지를 닫거나 새로고침할 때까지 남는다.
- 접속 코드를 설정했다면 모든 개인 API에도 같은 인증이 적용된다. 코드와 입력값은 로컬 스토리지에 저장하지 않는다. 기본 실행은 루프백 주소이며 외부 공개를 만들지 않는다.

출처가 추가되면 별도 어댑터와 파서 검증을 추가하고 출처별 실패를 유지한다. 접근 제한을 다른 계정이나 주소로 우회하지 않는다. 지속 가능한 앱 운영은 **수집 실패를 격리하고 직접 입력으로 계속 쓰는 것**을 뜻하며, 실시간 자동 검색의 영구적인 가용성을 보장하는 것은 아니다.

## API와 검증

| API | 역할 |
| --- | --- |
| `GET /api/v2/personal/options` | 도시·지역과 검색 가능 여부 |
| `POST /api/v2/personal/search` | `{subject}`로 비동기 검색 시작 |
| `GET /api/v2/personal/search/{job_id}` | 진행 상태·결과; 만료 시 404 |
| `POST /api/v2/personal/search/{job_id}/cancel` | `{}`로 대기 결과 취소 |
| `POST /api/v2/personal/compare` | `{subject,listings}`로 선택 표본 비교, 최대 60개 |

`python -m pytest -q`와 `node --check frontend/v2/personal.js`로 오프라인 회귀를 실행한다. 실제 사이트 검증은 수동 실행하며 CI에서 외부 사이트를 자동 호출하지 않는다. 실제 검증 결과는 단계 문서에 날짜와 함께 기록한다.
