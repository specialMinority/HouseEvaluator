# 한국인 대상 제한 공개 사용성 검수 양식

상태: **실제 참여자 검수 미실시**. 아래는 진행자가 사용할 계획과 기록 양식이다. 예시나 합성 시연을 통과한 결과를 실제 사용자·실제 시장 검수로 기록하지 않는다. 참여자 없이 `passed=true` 보고서를 작성하거나 준비 검사를 통과시키기 위한 JSON을 임의로 만들지 않는다.

대상은 일본 워킹홀리데이 또는 취업을 준비하는 한국어 사용자다. 검수 전에 참여자가 이해하는 일본 부동산 용어, 일본 거주 경험, 사용 기기를 간단히 기록한다. 이름·연락처·여권 등은 이 양식에 수집하지 않고 익명 참여자 ID를 사용한다. 실제 매물 자료는 표시·검증용 사용권이 있는 범위에서만 제공한다.

## 시행 정보

| 항목 | 실제 시행 후 기록 |
| --- | --- |
| 검수 일시·진행자 | 미정 |
| 참여자 수·익명 ID·대상 조건 | 미정 |
| 대상 도시·평면·검증 승인 구간 | 미정 |
| 실행 이미지·코드 버전·context_fingerprint | 미정 |
| 실제 자료/합성 자료와 공급 확인 시각 | 미정 |
| 브라우저·PC/휴대폰 화면 크기 | 미정 |
| 검수 기준 고정 시각·관찰 기록 보관 경로 | 미정 |
| 후속 수정·재검수 담당자 | 미정 |

공개 전 계획에서 참여자 수와 도시별 배정을 정한다. 최소한 도쿄·오사카·후쿠오카를 모두 다루고 일본 초보자의 휴대폰 흐름을 포함한다. 소규모 사용성 검수는 전체 이용자에 대한 통계적 정확도 보증이 아니다. 실제 승인되지 않은 구간은 보류 흐름만 검수한다.

## 과제와 관찰 기준

진행자는 먼저 답을 설명하지 않고 참여자가 화면을 읽고 자기 말로 설명하도록 한다. 선택 실수·주저한 곳·도움 요청과 실제 발언을 기록한다. 비싸거나 저렴한 결과는 미리 승인된 실제 자료에서 찾되 원하는 결론을 만들기 위해 매물 가격이나 조건을 바꾸지 않는다. 필요한 사례가 없으면 미실시로 남기고 별도 합성 시나리오임을 명시한다.

| 과제 | 관찰할 행동·질문 | 공개 전 확인할 이해 |
| --- | --- | --- |
| 세 도시에서 입력 | 도시·역·평면·면적·준공연도·구조·관리비를 읽고 입력 | 도시나 역을 잘못 고른 상태를 알아차리고 수정함 |
| 월세가 높은 사례 | 결과와 비교 매물을 본 뒤 판단 이유 설명 | 관리비 포함 기준과 유사 조건 모집가격 비교를 이해함 |
| 월세가 낮은 사례 | 결과를 보고 추가로 확인할 내용 설명 | 저렴함을 하자 없음·계약 가능·외국인 입주 가능 보장으로 오해하지 않음 |
| 판단 보류 사례 | 공급 없음·오래된 자료·표본 부족 중 제공된 사례 설명 | 보류를 적정 가격 또는 안전 판정으로 해석하지 않음 |
| 합성 시연 | 시연을 켜고 결과 출처 설명 | 합성 매물·시연 결과가 실제 시세가 아님을 구별함 |
| 근거와 조건 완화 | 비교 수·확인 시각·조건 완화 항목을 찾아 설명 | 일치한 조건과 완화된 조건, 결과 불확실성을 구분함 |
| 초기 비용 | 월세 외 보증금·사례금·중개비·보증료 등 제공값으로 총액 읽기 | 미입력 비용을 0엔으로 단정하지 않고 환급 가능 보증금과 지출을 구분함 |
| 거주 기간 비용 | 6/12/24개월을 바꾸어 금액 차이 설명 | 선납 월세의 중복 여부와 기간별 환산 의미를 이해함 |
| 접속 코드와 휴대폰 | 코드 입력·틀린 코드 수정·코드 삭제·재접속 | 오류에서 회복하고 작은 화면에서도 결과 근거를 읽음 |

## 관찰 기록

참여자별·과제별로 한 행을 작성한다. 관찰되지 않은 항목은 추정해 채우지 않는다.

| 익명 ID | 도시·과제 | 기기 | 완료/도움 필요/미실시 | 실제 발언·행동 | 오해·문제 | 영향 | 조치·재검수 결과 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 미실시 | — | — | 미실시 | — | — | — | — |

영향은 다음처럼 기록한다.

- 공개 차단: 보류·합성 자료를 실제 가격 판정으로 이해하거나 비용을 크게 잘못 해석하는 등 핵심 판단을 잘못하게 만드는 문제.
- 수정 후 확인: 입력·오류 회복·근거 탐색이 막혀 진행자 도움이 필요한 문제.
- 개선: 과제는 완료했으나 표현이나 배치가 이해를 지연시키는 문제.

공개 전에는 계획한 필수 과제를 실제로 수행하고, 공개 차단 문제를 해결한 뒤 같은 유형의 참여자에게 재검수한다. 미실시 과제·도시·기기는 보고서에 남기며 전체 통과로 처리하지 않는다. 통과 기준을 결과를 본 뒤 완화했다면 사유와 변경 시각을 기록하고 재검수한다.

## 증거와 승인

최종 내부 보고서에는 시행 정보, 익명 참여자 구성, 과제별 관찰, 문제와 수정, 재검수 결과, 남은 제한과 판단한 운영자를 포함한다. 실제 검수 없이 수치·발언·참여자·결론을 작성하지 않는다. 원자료를 공개 저장소에 넣지 않으며 보고서 보관 위치와 기간을 정한다.

실제 자료를 사용한 검수가 완료된 뒤 운영자가 근거를 검토하여 `kind=usability_review`, 실제 `checked_at`, 해당 실행의 `context_fingerprint`와 결론을 기록한다. 공개 준비 검사에서 인정할 수 있는 증거는 `scope=market_operations`이며 30일 이내여야 한다. 합성 자료 또는 진행자 혼자 한 점검은 실제 사용자 검수를 대체하지 않는다. 보고서의 상세 근거와 결론이 확인된 뒤에만 SHA256을 [운영 증거 설정](../config/release_evidence.example.json)에 등록한다. 양식 작성·해시 등록 자체가 사용성 통과를 보장하지 않는다.

현재 실제 참여자·실제 공급 자료·사용성 통과 보고서는 없다. 이후 시행 결과와 공개 결정은 [단계별 진행표](../DEVELOPMENT_PHASES.md)에 별도로 반영한다.
