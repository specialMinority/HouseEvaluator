# v2 로컬 스냅샷 반입과 운영 경계

이 문서는 `docs/V2_CONTRACT.md`의 데이터 인터페이스 사용법이다. 현재 구현은 운영자가 권리와 내용의 진위를 확인한 **완전한 로컬 JSON 스냅샷**을 읽는다. 외부 사이트나 URL을 요청하지 않는다. JSON의 `rights` 필드를 작성하는 행위는 계약 체결이나 실제 이용권 증명이 아니다. 운영자는 계약 문서와 샘플 검수를 먼저 완료해야 한다.

## 반입 명령

저장소 루트에서 실행한다. 런타임 DB와 공급 파일은 공개 정적 파일 디렉터리 밖에 둔다.

```powershell
python scripts/import_v2_snapshot.py runtime/supplier-snapshot.json --db runtime/observations.sqlite3
```

- UTF-8 JSON 하나를 최대 **20 MiB**, 최대 **10,000개 관측**까지 읽는다. HTTP URL·SQLite URI·UNC 공유 경로는 받지 않는다.
- JSON 중복 키, NaN/Infinity, 알려지지 않은 필드, 잘못된 타입은 거부한다. 숫자 문자열을 숫자로, `0`/`1`을 불리언으로 바꾸지 않는다.
- `complete=true`인 스냅샷만 받는다. 빈 스냅샷으로 공급원의 현재 목록을 전부 제거하려면 `--allow-empty`를 명시해야 한다.
- 합성 데이터는 기본 거부한다. 개발자가 `--allow-synthetic`을 명시한 반입만 가능하며, 실제 관측 모드와 별도로 읽는다. 합성 관측은 공개 매물 URL을 가질 수 없다.
- CLI 결과는 `imported` 또는 `unchanged`와 공급원·스냅샷 ID, 관측 수, 내용 해시다. 검증 거부/로컬 I/O 오류는 종료 코드 `2`다.

## 파일 계약

아래 구조의 `listings`에 계약에 맞는 개별 관측을 넣는다. 표시는 구조 예시이며 미래 권리 날짜를 임의로 작성해 운영 권한으로 간주하면 안 된다.

```json
{
  "schema_version": "2.0",
  "snapshot_id": "supplier-batch-0001",
  "as_of": "2026-09-13T03:00:00Z",
  "complete": true,
  "source": {
    "source_id": "supplier-a",
    "independent_source_id": "upstream-owner-a",
    "display_name": "계약으로 확인한 공급원 표시명",
    "data_kind": "observed",
    "rights": {
      "comparison": true,
      "display": true,
      "storage": true,
      "expires_at": "2026-10-01T00:00:00Z"
    }
  },
  "listings": []
}
```

각 관측에는 Subject 필드와 `unit_id`, `building_id`, `source_id`, `listing_id`, `observation_id`, `status`, `received_at`, `data_kind`가 필요하다. `source_updated_at`, `status_verified_at`, `public_url`은 미상이면 `null`이다. `unit_id`와 `building_id`는 공급원 간 중복을 식별할 수 있도록 반입 담당자가 정규화해야 한다. 가격이나 URL 일부로 같은 집임을 추정하지 않는다. 같은 공급원 스냅샷 안의 `listing_id`·`observation_id` 중복은 거부한다. 서로 다른 광고가 동일 `unit_id`를 가질 수 있으며 비교 엔진이 충돌을 검사한다.

시각은 `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` 또는 명시적 `±HH:MM` 오프셋이 있는 ISO 형식이며 UTC로 정규화된다. 날짜만 있는 값과 시간대 없는 값은 받지 않는다. 반입 당시 미래 시각, 관측 시각이 스냅샷 `as_of`보다 늦은 자료도 거부한다. 수신 시각·원문 갱신 시각·상태 확인 시각은 각각의 사실대로 제공해야 한다. 미상 시각에 수신 시각을 복사하면 안 된다.

역 ID는 앞뒤 공백만 제거하고 그대로 비교한다. `小岩`과 `新小岩` 또는 대소문자가 다른 코드를 임의로 합치지 않는다. `municipality`는 공급원과 사용자 입력이 같은 정규 코드/표기를 사용해야 한다. 행정구·역 코드 사전과 외부 공급사 매핑은 현재 공급 계약 이후 구축해야 하는 운영 작업이다.

Subject의 구조·연도·역 도보·층·방향·욕실 분리·가구·관리비가 누락되면 `null`로 보존한다. 관리비 미상을 0엔으로 치환하지 않는다. 입력 보호 한도는 면적 0.01–10,000㎡, 월세 1–1,000,000,000엔, 관리비 0–1,000,000,000엔, 건축연도 1800–평가 당시 연도, 도보 0–1440분, 층 -20–200이다. 이 범위는 지원 가능한 입력 범위이며 시장 분포를 뜻하지 않는다.

## 원자적 교체·재현성

공급원마다 마지막으로 승인된 완전 스냅샷 하나가 현재 자료다. 더 새로운 스냅샷의 반입은 이전 목록을 통째로 대체하므로 새 목록에서 빠진 매물이 남지 않는다. 종료 상태 행은 보존하되 비교 엔진이 비교 대상에서 제외한다.

SQLite `BEGIN IMMEDIATE` 트랜잭션으로 현재 데이터와 해시 영수증을 함께 쓴다. 둘 중 하나의 쓰기가 실패하면 둘 다 되돌린다. HTTP 여러 스레드에서도 호출마다 별도 연결을 사용한다. 입력의 키 순서·관측 순서는 내용 해시에 영향을 주지 않는다. 공개 `snapshot_version`은 실제 읽기 가능한 공급원별 내용 해시와 관측/합성 모드에서 계산되므로 DB 위치나 반입 순서에 의존하지 않는다.

- 같은 `source_id`·`snapshot_id`·내용의 재반입은 `unchanged`다.
- 이미 사용한 스냅샷 ID에 다른 내용을 붙이면 거부한다.
- 처음 보는 스냅샷의 `as_of`가 현재 스냅샷보다 같거나 오래되면 거부한다.
- 과거에 승인된 정확한 스냅샷 재전송은 영수증만 확인하고 현재 자료를 과거로 되돌리지 않는다.
- 같은 공급원 ID를 관측에서 합성 또는 반대로 전환할 수 없다. 새로운 개발 공급원 ID를 사용한다.
- 반입 당시 만료된 권리는 재반입을 포함하여 거부한다.

## 평가 시 권리와 상태

`read_current()`는 매 호출마다 comparison/display/storage가 모두 `true`인지, 권리가 현재 시각보다 뒤에 만료되는지 확인한다. 권리 만료 시각과 동일한 시각부터 해당 공급원의 전체 관측과 메타데이터가 결과에서 빠진다. 현재보다 미래의 스냅샷과 내용 해시가 깨진 스냅샷도 제외한다. 모집 상태·24시간 최신성·조건 일치 여부는 그다음 비교 엔진이 검사한다.

`include_synthetic=False`는 실제 관측만, `True`는 합성만 읽는다. 실데이터가 없을 때 자동으로 합성 또는 과거 집계표를 반환하지 않는다. `health()`에는 개수와 가용 상태만 있으며 파일 경로·원문·계약 내용은 포함하지 않는다. API에 공급권을 작성하거나 반입하는 기능은 없다.

## 현재 구현의 운영 한계

합성 데모는 도쿄·오사카·후쿠오카 각각 24호실·12건물이며 평가 대상과 모든 비교 호실의 식별자가 다르다. 가격·특성은 고정 개발 예시이고 시각은 `now`를 기준으로 만든 명시적 시뮬레이션이다. 실제 가격 정확도나 공급 지연 검증 자료로 쓸 수 없다.

현재 DB는 이전 원문 스냅샷을 보관하지 않고, 재전송 검출용 해시 영수증만 남긴다. 따라서 이전 평가의 원문 재현과 30일 시장 검증에는 허가된 별도 이력 보관이 필요하다. 현재 수집기의 최근 사건 로그만으로 과거 원문·내부 가용 시각·적용 완료 시각을 복구할 수는 없다. 이력 보관 기간에 대한 허용 범위와 수집 연결을 추가로 준비해야 한다.

Phase 7.3에서 SQLite 온라인 백업·신규 경로 복구·만료/철회/보관기한 정리 명령을 구현했다. `--suppliers`로 현재 계약 설정을 연결할 수 있으며 정리는 기본 계획 출력, `--apply`로 실제 적용한다. 자동 실행 일정과 원격 사본은 아직 구성하지 않았다. 자세한 범위는 [저장 수명주기 안내](STORAGE_LIFECYCLE_V2.md)를 따른다. 실제 공급·ID 매핑·현장 검수·갱신 주기와 이력 보존 권한은 실제 데이터 연동과 출시 전에 확보해야 한다.
